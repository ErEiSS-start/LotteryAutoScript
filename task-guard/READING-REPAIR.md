# 专栏正文和中奖私信扫描修复

修复两条已复现的告警：武汉五篇专栏网页返回异常短页面，导致整轮拒绝提交快照；美国账号的私信列表参数未显式设置分类和排序，翻页到上限仍未覆盖未读计数。

## 读取行为

- 已关注/系统会话使用 `session_type=9`，未关注使用 `2`，明确设置折叠参数、`sort_rule=2` 和每页 20 条。调用方仍使用原有内部分类 1/2。
- 保留原页数上限和 -509 重试；修正页数边界。重复置顶会话只计数一次，游标取非置顶会话的最早时间，不让置顶顺序造成跳页或重复计数。
- 只有覆盖预期未读或服务端明确返回列表末尾才结束。到末尾仍与汇总计数不符时说明计数不一致；页失败、达到上限、游标停滞仍判不完整。
- 正常返回空私信属于正常结果；接口失败或响应结构异常仍记录失败。不会标记平台消息已读，不修改中奖分类规则或每会话现有读取范围。
- 专栏 HTML 与 Opus 网页都无效时，额外调用一次正文 JSON 接口，携带 `htmlNewStyle`。核验响应成功、图文 ID 和正文模块结构，仅提取正文文字与链接，排除作者信息、统计、图片文件名和推荐列表中的数字 ID。
- 所有入口仍失败时保留原有“不完整采集不得提交快照”策略；不会将任意空白、错误页面或回退指示误当有效正文。

接口字段参考：[私信接口记录](https://github.com/huang3292/bilibili-API-collect-save/blob/master/docs/message/private_msg.md)、[Opus 正文接口记录](https://git.xfe.studio/XFEstudio/bilibili-API-collect/Blob?branch=master&path=docs%2Fopus%2Fdetail.md)。实际行为同时使用受影响服务器只读验证。

## 验证和部署

`test/alert_reading_regression.test.js` 覆盖置顶去重、游标、页数上限、末尾计数不一致、空私信、错误响应、正文 JSON 回退及失败仍阻断快照；原专栏和中奖通知测试一并运行。

只读验证中，五篇失败专栏均返回合法正文并可提取引用；美国修正参数后的两类列表首次全列表探测分别在 8 页、24 页到达末尾。上线后使用实际 Node 适配器再次验证，分别在 5 页、11 页覆盖当时的预期未读计数并正常停止。两次观测的实时数据不同。只读验证不读取私信正文、不更新已读状态、不发送通知，也不运行抽奖。

部署顺序为武汉、新加坡、美国。代码位于独立 `20261030-reading-fix-v1/lottery`，只切换后续自动抽奖和中奖检查入口；执行时间、账号、互动策略、业务状态文件、每日升级及原监控保留。失败的任务不自动补跑，也不伪造“已恢复”；下一次正常定时执行明确成功后，监控再发送恢复通知。

回滚：在宿主机执行 `python3 DATA/task-guard/rollback_reading_repair.py DATA`。它恢复之前的两个入口，保留统计、失败监控、正在运行的任务和业务进度。备份位于 `DATA/backup/reading-repair-20261030-v1`。
